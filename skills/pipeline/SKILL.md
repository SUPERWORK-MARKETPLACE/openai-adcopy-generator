# 생성 파이프라인 (순서 고정 — 건너뛰기 금지)

## 0. 바이너리 선택

adcopy CLI 경로 (OS에 맞게 택1):
- Windows: `${CLAUDE_PLUGIN_ROOT}/bin/adcopy-windows-amd64.exe`
- macOS(Apple Silicon): `${CLAUDE_PLUGIN_ROOT}/bin/adcopy-darwin-arm64`
- macOS(Intel): `${CLAUDE_PLUGIN_ROOT}/bin/adcopy-darwin-amd64`

이하 `adcopy`로 표기. 종료 코드: 0 정상 / 1 검증 위반 발견 / 2 실행 오류.

## 1. 작업 폴더

입력 워크북과 같은 위치에 `<파일명(확장자 제외)>.adcopy/` 폴더를 만들고 모든 중간 산출물을 저장:
`workbook.json`(입력 덤프) → `urls.json`·`urlcheck.json` → `generated.json` → `validate-report.json` → `review.xlsx`. 세션이 끊겨도 이 파일들로 재개한다.

## 2. 입력 검증 (생성 시작 전 — 실패 시 부분 진행 없이 중단·보고)

1. `adcopy inspect <입력.xlsx>` → `workbook.json` 저장. DRM/암호화 오류면 "표준 xlsx로 다시 저장해 주세요"라고 안내하고 중단. 각 시트의 `preamble`(헤더 위 제목·안내 행)도 읽는다 — 작성 지침이 들어 있을 수 있다.
2. 덤프에서 시트·필드 파악: campaigns(필수), 상품·브리프, 이미지소재, 고객질문·검색데이터, 주력 키워드, 정책·참고자료. campaigns 또는 브리프(상품·대표 랜딩 URL)가 없으면 중단·보고.
   - **시트명은 부분 일치로 찾는다** — 실물 템플릿은 "(추가자료)고객질문·검색데이터(있을경우)"처럼 접두·접미가 붙는다. "작성안내" 등 순수 안내 시트는 입력 데이터로 쓰지 않는다.
   - **campaigns의 템플릿 가이드 행 제외:** 값이 "Required"인 행, 영문 필드 설명 행은 데이터가 아니다. 실제 캠페인 행만 취한다.
   - **숫자 정규화:** `budget_max`가 `" 25,000 "`처럼 서식 문자열이면 공백·콤마를 제거해 숫자로 변환한다(generated.json은 숫자 타입).
   - **`campaign_name = "공통"` 행(고객질문·주력키워드 시트):** 특정 캠페인 소속이 아니라 **전 캠페인·전 SKU 공통 적용** 의미다 — 참조 오류로 취급하지 마라.
3. 모든 랜딩·이미지 URL을 모아 `urls.json`(`{"urls": [...]}`)으로 저장 → `adcopy checkurls urls.json`. **URL 형식(`http(s)://`)인 값만 수집한다** — 정책·참고자료 시트의 파일명·텍스트 참조는 제외. 실패 URL이 있으면 **생성 전에** 목록 보고 후 중단 (운영자가 계속 진행을 명시적으로 지시한 경우에만 해당 소재 제외하고 진행).
4. 프로모션 종료일이 지난 소재는 생성 대상에서 제외하고 제외 사유에 기록.
5. 이미지 소재를 확인해 **로고가 화면의 주가 되는(로고 메인) 소재는 표시**하고 운영자 확인을
   받는다(charter §6 이미지 규칙). 이미지 치수(1:1, 640~1200px) 자동 검증은 v1 이월 — 운영자
   육안 확인에 의존함을 보고에 명시한다.

## 3. 조건 설정 (운영자 대화)

- **필수 질문 — 전체 카피 생성 목표 개수(반드시 답을 받는다):** 생성 시작 전 운영자에게 목표
  개수를 직접 질문한다. **무응답·기본값 진행 금지** — 답을 받기 전에는 생성을 시작하지 않는다.
  운영자가 숫자를 정하기 어려워하면 입력 자료 기반 AI 추천값(§8-1 슬라이스 추정)을 제시하고
  **명시적 확정**을 받는다. 확정된 목표가 품질 유지 상한을 넘으면 §8-1 워닝 후 **목표대로
  강행**한다(선택 라운드 없음). 목표 개수로 §8 대량 생성 모드 여부를 판단한다.
- 나머지는 AI 추천 기본값을 제시하고 조정을 받는다: 포함/제외 퍼널 단계(기본: ①~⑤ 포함,
  ⑥ 사용도움은 제외), 단계별 비중, 광고그룹 수, 광고그룹당 카피 수(기본 2~3), 검수 엄격도.
  이 항목들은 운영자가 무응답이면 기본값으로 진행하되 보고에 명시(목표 개수만은 예외 없이 필수).

## 4. 생성 (adcopy:context-expansion, adcopy:copy-rules 스킬 로드 후)

- 맥락 확장 → 광고그룹 → Context Hints → 제목·카피 → URL 연결 순. 상품 정보를 바로 카피로 바꾸지 말 것.
- **정책 반영:** 정책·참고자료 시트의 공통 금지어를 읽어 SKU별 금지 표현과 병합해 최상위 `policy.banned_terms`를 채운다. **금지 표현**은 한 셀에 콤마(,)로 연결된 목록이다 — 항목별로 분리하고 앞뒤 공백을 트림한다.
- **카피 핵심 반영 요소(워크북 v2):** 상품·브리프 시트의 "카피 핵심 반영 요소" 컬럼은 그 SKU의 혜택·조건·특징 키워드/짧은 구문 **후보군**이다 — 한 셀에 `/`로 연결된 목록(예: "무료학습 체험 / 아이 영어 수준 진단 / 체험 후 결정"). **반드시 포함이 아니다** — 광고별로 상황·퍼널 단계에 맞는 **1~2개를 골라 재구성**한다(동등 의미 표현 허용, verbatim 의무 없음). 사용한 요소는 `trace.generation_basis`에 `핵심요소=...`로 기록한다. 기계 검사 대상이 아니며 의미 검수(§6-3)에서 반영 여부를 자체 점검한다. 구버전 워크북의 "필수 포함 문구" 컬럼을 만나면 같은 방식(후보군)으로 처리한다.
- **매칭 제외 게이트:** **정책·참고자료 시트의 "매칭 제외 주제"를 최우선 게이트로 적용**하고, 공통 하드 게이트(채무·연체·신용등급·미성년자 발급·도박·개인 금융 취약성 추정)를 더한다. 걸리는 페르소나·맥락은 생성 전에 필터한다(context-expansion 정책 게이트).
- **광고그룹 단위로 생성해 `generated.json`에 누적 저장** (대량 생성 시 컨텍스트 관리). 규모가 크면 광고그룹별 서브에이전트로 분산.
- 소재별 랜딩 URL이 있으면 `link`에 우선 적용, 없으면 대표 랜딩 URL.
- 브리프·랜딩·이미지 간 정보가 충돌하는 항목은 생성하지 말고 `validation_status: "광고주 확인 필요"`로 표시.

## 5. generated.json 스키마 (CLI 계약 — 필드명·타입 엄수)

```json
{
  "policy": { "banned_terms": ["무조건 발급", "누구나", "최고", "반드시 절약", "혜택 보장", "업계 1위"] },
  "campaigns": [{
    "campaign_name": "01_학습자료", "budget_max": 25000, "budget_type": "daily",
    "launch_date": "2026-07-01", "end_date": "2026-07-31",
    "objective": "Views", "target_countries": ["KR"]
  }],
  "adgroups": [{
    "campaign_name": "01_학습자료", "adgroup_name": "훈련앱_초등학부모_반복훈련필요_제품발견",
    "keywords": [{"text": "초등 영어 앱은 어떤 걸로 시작하면 좋을까?", "origin": "customer_data"}],
    "trace": {"source_type": "브리프", "source_url": "", "source_excerpt": "매일 10분 반복 훈련으로 영어 습관 형성",
      "generation_basis": "SKU=...; Persona=...; 문제=...; 상황=...; 퍼널=제품발견; 세부의도=...; 메시지=...",
      "confidence_score": 0.9, "validation_status": "", "review_comment": "", "exclusion_reason": ""}
  }],
  "ads": [{
    "ad_name": "KID_01_001", "adgroup_name": "훈련앱_초등학부모_반복훈련필요_제품발견",
    "title": "...", "copy": "...", "link": "https://...", "image_link": "https://...",
    "trace": { "...": "adgroups와 동일 구조" }
  }]
}
```

- `keywords[].origin`: 실제 고객 데이터 기반이면 `customer_data`, AI 추론이면 `ai_inferred` (결과에서 구분 표시 의무).
- `adgroup_name`은 `상품/SKU_타깃_세부의도_구매여정` 4슬롯 형식 — 마지막 슬롯(중복 순번 숫자 접미 앞)은 퍼널 6개 고정 토큰(문제정의·제품발견·비교검토·단일제품평가·신청전환·사용도움) 중 하나만. `generation_basis`의 `퍼널=` 값도 동일 토큰. validate가 `adgroup_name_format` 규칙으로 경고 검사(차단 아님).
- **`trace.source_excerpt`**: `source_type`이 ai_inferred가 아니면 **근거 원문 발췌 필수** — 빈칸이면 validate가 `source_excerpt_missing` 경고(광고 ads trace에 적용; `source_type` 빈칸은 검사 대상 아님).
- **`trace.validation_status` = AI 자동 검수 결과·노트 필드.** 표준 플래그 어휘 8종 — `의미 중복 후보`·`경고`·`광고주 확인 필요`·`길이 초과`·`길이 권장 초과`·`근거 확인 필요`·`정책 확인 필요`·`문장 자연성 확인 필요` — 로 기록한다. 정보 충돌은 "광고주 확인 필요", 근거 부족은 "근거 확인 필요", 노트는 토큰을 접두로("의미 중복 후보: <ad_name>", "정책 확인 필요: 1위 표현 출처 불명확"). **`trace.review_comment`는 운영자·광고주 기입란 — AI가 채우지 않는다(항상 빈 문자열).**
- **`max_bid`는 절대 쓰지 않는다** — 값이 있으면 validate가 오류로 잡는다.
- `campaigns`는 입력 워크북 값을 그대로 옮긴다(AI가 지어내지 않음).
- `ad_name` 형식: `캠페인/SKU 코드 + 광고그룹 코드 + 크리에이티브 순번` — **순번 앞 프리픽스가 광고그룹마다 달라야 한다**(예: 같은 SKU의 그룹 2개면 `KID_01A1_001`·`KID_01A2_001`). SKU 코드 하나로 순번 범위만 나눠 그룹을 구분(`KID_01A_001~009`가 그룹 3개 커버)하면 validate가 `ad_name_format`으로 경고. 내부 관리용 — 업로드 파일에는 포함되지 않는다.
- **`policy.banned_terms`**(최상위·optional): 정책 시트의 **공통 금지 표현 + SKU별 금지 표현**을 병합한 전역 문자열 목록. validate가 각 표현(공백 트림)을 **모든 ad의 title·copy와 모든 adgroup의 keyword.text**에서 `strings.Contains`로 찾아 있으면 `banned_term` 오류. 없으면 검사 스킵(하위호환).
- **카피 핵심 반영 요소는 generated.json에 실리지 않는다** — 생성 시점 가이드(§4)이며 기계 검사 필드가 아니다. 반영 근거는 각 광고의 `trace.generation_basis`(`핵심요소=...`)로 남긴다.

## 6. 자동 검수 루프

1. `adcopy validate generated.json` → `validate-report.json`.
2. errors가 있으면 해당 항목만 재생성/수정 후 재실행 (최대 3회 반복, 그래도 남으면 해당 항목 제외 + 제외 사유 기록).
   - `banned_term`(금지어 포함)은 **해당 광고만** 카피를 고쳐(금지어 제거) 재실행한다.
3. 형식 검증과 별개로 의미 검수를 스스로 점검: adcopy:copy-rules의 금지 규칙, 광고그룹 간 Context Hints 중복·범용 문구 반복·힌트 내 여정 의도 혼합(context-expansion 규칙 — 중복 금지는 캠페인 무관 전역), 동일 광고그룹 내 종결형 분산·CTA형 종결 30% 이하(copy-rules 메시지 다양성), **그룹별 힌트 유형 카운트 — 검색어형 40%/질문·상황형 60%(±10%, 검색어형 30~50%) 범위인지 세어 확인 + 검색어형 힌트마다 {상품/SKU·타깃·세부 의도·구매여정} 중 2개 이상 드러났는지 확인**(범위 밖·요소 부족은 재작성), **title/copy 문장 자연성**(copy는 완결 문장 + copy-rules anti-pattern 전항목 — 설명문투·문어체 서술어(견주다류)·명사 적층·연어 오류·어미 부조화·어색한 조사/어순, 문제 발견 시 "문장 자연성 확인 필요" 기록), **title+copy 연결성**(copy-rules S5 전체 기준 — ①copy가 title 핵심어 단순 반복·어절 재배열, ②title 고민을 다른 말로 반복만 하고 해결 방향 부재, ③title 질문에 copy가 다시 질문(0715 — ②③은 기계 검사가 못 잡는 케이스 포함, 유일한 방어선이 이 점검이다) 발견 시 "의미 중복 후보" 플래그 + 재작성), **ai_inferred 광고 전수 점검**(상품 기능·측정 지표·수치·제3자 사용 등 상품 사실 주장이 들어 있으면 근거를 찾아 출처를 바로잡거나 재작성/"근거 확인 필요" 플래그 — copy-rules 사실성), **사실 인용 광고의 근거 승격 점검(4차 실측)**(copy가 "바탕으로·통해·기반으로·덕분에"로 사실을 잇거나 "객관적으로" 등 정도 부사를 쓰면 `source_excerpt`와 대조 — 발췌가 나열뿐인데 인과·수단으로 결합했거나 근거에 없는 정도 강화면 재작성 또는 "근거 확인 필요" — copy-rules 근거 승격 금지), **copy 어체 통일 점검**(해요체·합니다체 — 반말 평서형은 재작성), **사실 인용 광고(`source_type`이 ai_inferred가 아닌 광고)의 `source_excerpt` 채움 확인**.
4. **warnings도 방치하지 마라 — 단, 수정 라운드는 1회:** `keyword_searchform_ratio`·`keyword_cross_adgroup_duplicate`·`copy_cta_ratio_30`·`copy_sentence_form`·`copy_speech_level`·`title_copy_overlap`·`title_copy_question_repeat` 경고는 해당 그룹의 힌트·카피를 재작성해 해소하고, `source_excerpt_missing` 경고는 근거 원문 발췌를 채워 해소한다. `title_len_recommended`/`copy_len_recommended` 경고가 전체 광고의 과반이면 해당 그룹들을 권장 길이에 맞춰 재생성한다. **경고 수정은 한 라운드만** — 라운드 후 남은 경고는 검수 워크북으로 그대로 전달한다(플래그 행 처리). 대량 생성 모드에서는 §8-2 셀프 검증이 이 작업 대부분을 생성 단계에서 흡수하므로, 여기서는 교차 청크 잔여분만 처리한다(수정 에이전트를 띄울 땐 병렬로).

## 7. 검수 워크북 출력·보고

1. `adcopy review-out generated.json -o review.xlsx --report validate-report.json` — 리포트를 넘기면 행별 자동 검수 결과(오류·경고 유형)가 `validation_status` 열에 병합된다. 문제 없는 행은 "통과". 광고주 판정은 별도 `검수상태` 드롭다운 열(4종: 무수정 승인·수정 후 승인·사용 불가·부분 재생성)로, **전 행 빈칸이 기본값**(0715 요청 1) — review-out은 어떤 값도 미리 기입하지 않고, 플래그는 `validation_status` 열에서만 확인한다. `광고주 확인 필요`는 validation_status 전용 플래그이며 검수상태 값이 아니다.
2. 운영자에게 보고: 생성 수량(캠페인/광고그룹/광고), 제외 항목과 사유, 자동 검수 플래그 행 건수(`광고주 확인 필요` 등 validation_status 기준), 자동 검수 결과 요약, review.xlsx 경로와 다음 단계(엑셀 검수 → `/adcopy:finalize`).
3. 자동 검수는 **오류 후보 선별일 뿐** — 최종 판단은 운영자·광고주가 한다는 점을 함께 안내.

## 8. 대량 생성 모드 (목표 카피 수가 큰 경우)

목표 카피 수가 약 40개를 넘거나 광고그룹이 10개를 넘을 것으로 예상되면 이 절차를 적용한다.

### 8-1. 품질 유지 상한 추정 → 워닝 (생성 시작 전 필수)

1. adcopy:context-expansion 규칙으로 **자연스러운 맥락만** 선별해 슬라이스 계획을 세운다:
   포함 퍼널 단계 × 페르소나 × 메시지 각도 → 광고그룹 후보 수 × 그룹당 카피 수(2~5).
   그 곱이 **품질 유지 상한 추정치**다. 근거(축별 개수)를 함께 기록한다.
2. **목표 > 상한이면 워닝만 제시하고 목표 수량대로 강행한다**(§3에서 받은 목표 개수가 계약값 —
   추가 선택 라운드 없음). 워닝에 반드시 포함: 상한 추정치와 축별 근거, 초과분 규모, "초과분은
   동일 맥락의 로테이션 변형(표현·각도 변주)으로 생성되며 의미 중복 후보 표시(8-4)가 강화된다"는
   고지, 상한을 올리려면 상품/SKU·소재·고객 데이터 보강이 필요하다는 권고. 초과분 광고는
   `trace.generation_basis`에 `변형=로테이션`을 남긴다.
3. 목표 ≤ 상한이면 워닝 없이 슬라이스 계획만 보고하고 진행한다.

### 8-2. 분산 생성 (슬라이스 배타 할당)

- 슬라이스(퍼널×페르소나×메시지 각도 조합)를 서브에이전트에 **배타적으로 할당**한다 —
  슬라이스가 겹치지 않는 것이 곧 의미 중복 방지 장치다.
- 각 서브에이전트는 작업 폴더에 `generated-01.json`, `generated-02.json`… 청크를 쓴다
  (§5 스키마 동일). `campaigns`와 최상위 `policy`(banned_terms)는 모든 청크에 **입력 워크북 값 그대로 동일하게** 포함한다(SKU별 카피 핵심 반영 요소 후보군은 각 슬라이스의 브리프 사실 목록에 실어 보낸다).
- 각 서브에이전트에 adcopy:context-expansion·adcopy:copy-rules 규칙과 배정 슬라이스,
  브리프 사실 목록을 전달한다. ad_name 순번 충돌 방지를 위해 청크별 접두 코드를 배정한다
  (예: 01번 청크 → `KID_01x_###`). 청크 안에서도 **광고그룹마다 그룹 코드를 붙여 프리픽스를
  구분한다**(§5 ad_name 규칙 — 순번 범위로만 그룹을 나누면 `ad_name_format` 경고).
- **셀프 검증(필수 — 병렬 창 안에서 경고를 끝낸다):** 각 서브에이전트는 청크 작성 후
  `adcopy validate <자기 청크.json>`을 직접 실행하고(청크에 campaigns·policy가 있어 단독 검증
  가능) **자기 몫 오류·경고(`copy_speech_level`·`title_copy_overlap`·`title_copy_question_repeat`·`source_excerpt_missing` 포함)를
  스스로 해소한 뒤** 반환한다(최대 2회 반복). 병합 후 별도 수정
  에이전트를 다시 띄우는 것보다 이 방식이 훨씬 빠르다 — 컨텍스트가 이미 로딩돼 있고 전체
  병렬 창에 흡수된다. 단, 교차 청크 검사(그룹 간 힌트 중복 등)는 청크 단독으론 못 잡으므로
  병합 후 §8-3 검증이 최종이다.

### 8-3. 병합 → 검증

```
adcopy merge -o generated.json generated-01.json generated-02.json ...
adcopy validate generated.json
```
- merge는 campaigns를 이름 기준으로 중복 제거하고 **정의가 다르면 오류로 중단**하며,
  `policy.banned_terms`를 청크 전체에서 **합집합(순서 보존·중복 제거)**으로 보존한다 — 병합본에서도 금지어 검사가 유지된다.
- 교차 청크 중복(adgroup_name·ad_name·동일 title+copy)은 validate가 잡는다 —
  오류 항목만 해당 청크 담당 기준으로 수정 후 재병합한다(§6 루프와 동일, 최대 3회).

### 8-4. 의미 중복 검토 (병합 후 필수)

- 전체 제목·카피 목록만 모아 읽고(500건이어도 수십 KB) **의미가 사실상 같은 문구 후보**를
  찾는다. **광고그룹 간 Context Hints도 함께 훑어**(캠페인 무관 전역) 다른 그룹과 의미가 겹치거나 범용 문구가
  반복된 힌트를 후보에 넣는다(완전 동일·공백만 다른 문자열은 validate가 경고로 잡는다). 자동 삭제하지 말고 해당 광고의 `trace.validation_status`에 "의미 중복 후보: <상대 ad_name>"을
  기록한다(자동 검수 결과 필드 — review_comment는 운영자용이라 쓰지 않는다). 자동 검수는 후보 선별일 뿐, 제거 판단은 운영자 몫.
- **전역 표현 반복 점검(4차 실측)**: 같은 훑기에서 특이(비일상) 서술어·관용 표현이 여러 광고그룹에 반복되는지 본다(실측: '견주다'가 3개 그룹에 반복 — 의미 중복은 아니어도 템플릿 티가 난다). 발견하면 그룹별로 표현을 변주해 재작성한다(청크 셀프 검증은 자기 청크만 보므로 이 점검은 병합 후에만 가능).
- 목표 강행(8-1의 2 — 목표>상한)이었다면 로테이션 변형 광고에 `trace.generation_basis`의 `변형=로테이션` 기록을 확인하고, 변형 광고를 의미 중복 후보 검토의 우선 대상으로 삼는다.

  종료 등 제외분), 슬라이스 계획 요약, 의미 중복 후보 건수, 워닝 발생 내역(목표>상한 강행 여부·
